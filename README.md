# Capacitated Vehicle Routing Problem: Exact vs Heuristic

IT5082 Optimization Methods, programming assignment (group of 2).

We model delivery routing as a Capacitated Vehicle Routing Problem (CVRP) and
solve it with two methods:

1. **Exact:** a Mixed-Integer Linear Program (MTZ formulation) solved with CBC through PuLP.
2. **Heuristic:** a capacity-aware nearest-neighbour greedy construction, improved with Simulated Annealing.

The two are compared on solution quality (gap to the known optimum), runtime,
scalability and feasibility.

## Problem

One depot serves *n* customers. Customer *i* has demand *qᵢ*. There are *K*
identical vehicles, each with capacity *Q*. Every customer must be visited
exactly once, every route starts and ends at the depot, and no route may carry
more than *Q*. The goal is to minimise the total distance travelled.

The full formulation (sets, parameters, variables, objective and constraints)
is in the report. The constraints in `src/model_milp.py` are labelled C1–C5 to
match it.

## Data

Benchmark instances come from CVRPLIB
(https://galgos.inf.puc-rio.br/cvrplib):

| Instance | Customers | Vehicles | Capacity | Optimal cost |
|---|---|---|---|---|
| P-n16-k8 | 15 | 8 | 35 | 450 |
| E-n22-k4 | 21 | 4 | 6000 | 375 |
| A-n32-k5 | 31 | 5 | 100 | 784 |
| A-n45-k6 | 44 | 6 | 100 | 944 |
| A-n80-k10 | 79 | 10 | 100 | 1763 |

Distances are Euclidean, rounded to the nearest integer (the EUC_2D
convention used for the published optima).

Synthetic instances for larger sizes are generated by
`loader.generate_synthetic()`: customers spread uniformly over a square area,
depot in the centre, integer demands, and a fleet sized from total demand.

## Setup

Python 3.10 or newer.

```bash
git clone https://github.com/nisalgangana/optimization-assignment-cvrp.git
cd optimization-assignment-cvrp
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` installs PuLP 4 together with the CBC solver
(`pulp[cbc]`). PuLP 4 no longer ships CBC on its own, and its API differs from
PuLP 2.x, so an older PuLP will not run `src/model_milp.py`.

**macOS on Apple Silicon:** the `cbcbox` package ships three libraries with
broken code signatures, and macOS stops CBC as soon as it starts (exit code
137). Re-sign them once after installing (adjust `python3.14` to your Python
version):

```bash
codesign --force --sign - .venv/lib/python3.14/site-packages/cbcbox/cbc_dist/lib/{libgcc_s.1.1.dylib,libgfortran.5.dylib,libquadmath.0.dylib}
```

Check that the solver is available (the list should contain `COIN_CMD`):

```bash
python -c "import pulp; print(pulp.listSolvers(onlyAvailable=True))"
```

The instances are already in `data/instances/`; to download them again:

```bash
python src/download_instances.py
```

Check that the loader works:

```bash
python src/loader.py data/instances/P-n16-k8.vrp
```

## Design notes

Both solvers take an `Instance` and return a `Solution` (`src/common.py`).
The cost of a solution is always computed by `common.solution_cost`, and every
result is checked with `common.is_feasible`, so the two methods are measured
in exactly the same way.

`Solution.status` is one of `optimal` (proved by the solver), `feasible`,
`timeout` or `infeasible`. For the MILP we also store the solver's best lower
bound, so the optimality gap can be reported when it times out.

## Results

### Exact method (MTZ MILP, CBC)

Run one instance with `python src/model_milp.py <instance.vrp> <time_limit>`.

| Instance | n | Time limit | Status | Cost | Optimum | Gap to optimum | Lower bound | Runtime |
|---|---|---|---|---|---|---|---|---|
| P-n16-k8 | 15 | 120 s | optimal | 450 | 450 | 0.00% | 450.0 | 65.9 s |
| E-n22-k4 | 21 | 600 s | timeout | 466 | 375 | 24.27% | 261.3 | 600.7 s |
| A-n32-k5 | 31 | 600 s | timeout | 1144 | 784 | 45.92% | 424.0 | 601.4 s |

The MILP proves the optimum only on the smallest instance. On the larger ones
the lower bound stays far below the optimum (70% and 54% of it), so branch and
bound cannot prune the tree and the time limit is reached first.

The comparison with the heuristic (`results/results.csv` and the figures in
`results/`) will be added once both methods have been run.
